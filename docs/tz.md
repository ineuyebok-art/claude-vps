# ТЗ — Claude на своём VPS: Telegram + VS Code + рабочий стол сервера

Единственная актуальная версия. Остальные документы проекта (`claude/concept.md`, `code/hub/`, старые ТЗ) — не использовать как требования.

## 1. Цель
Одна команда ставит всё на VPS (4 vCPU, 8 ГБ RAM, 60 ГБ SSD, Ubuntu 24.04). Дальше:
- **телефон** — Telegram-бот: вопросы по файлам и фото, запуск задач и наблюдение за ними;
- **ПК / ноутбук (Windows)** — ярлыки: терминал с Claude, VS Code, рабочий стол сервера, папка `C:\Claude` (синхронизирована с сервером); для разговоров — тот же бот в Telegram Desktop;
- **вход в Claude и оплата** — рабочий стол сервера (VNC).

Claude Code и браузер для входа работают только на сервере → Anthropic видит только IP сервера.
Главный критерий — удобство: отдать файл, получить файл, посмотреть результат — одно действие на любом устройстве; ничего не помнить и не вводить. Ресурсов хватает — никаких очередей и оптимизаций.

## 2. Сценарии (обязаны работать)
1. На ПК идёт тяжёлая задача; одновременно в Telegram обсуждаю фото или файл — бот отвечает сразу.
2. Два моих Telegram-аккаунта: у каждого свои разговоры, задачи и файлы общие.
3. Отдаю файл в одно действие: в Telegram — фото/файл/ссылка на Google Диск, Яндекс Диск, Dropbox; на ПК — кинул в `C:\Claude\inbox` или перетащил оттуда в окно Claude, ПКМ → «Отправить → Claude», скриншот — Ctrl+Alt+V.
4. Получаю файл там, где работаю: в Telegram — сообщением; на ПК — он уже лежит в `C:\Claude\outbox`, Ctrl+клик по пути в ответе открывает его; копия приходит в Telegram.
5. Результат (страница, график, PDF, сайт) вижу в VS Code рядом с Claude.
6. Пока Claude в боте отвечает, задаю ещё вопрос — ответ идёт параллельно, контекст помнится.
7. С телефона запускаю, смотрю и останавливаю задачи (свои и с ПК), отвечаю на их вопросы кнопками; бот пишет «готово» / «ждёт тебя».
8. Начал на ПК — продолжил с телефона, и наоборот.
9. Вход в Claude и оплата — на рабочем столе сервера.

## 3. Состав и папки
**Сервер:** Claude Code (официальный нативный установщик, автообновление), tmux, Telegram-бот (Python, только stdlib), рабочий стол (TigerVNC + Xfce + Chromium из PPA xtradeb, не snap, + терминал; только 127.0.0.1:5901), SSH на порту 22 — единственный открытый порт (смена порта и fail2ban не нужны: вход только по ключу).
**ПК (ставит строка «Добавить ПК»):** VS Code (Microsoft) + Remote-SSH, Windows Terminal, TigerVNC Viewer, Mutagen (синхронизация папок по SSH; на сервер ставит своего агента сам).
**Нет:** веб-панели, домена, VPN, Docker, баз данных, облачных синхронизаций, голосовых, расширения Claude Code для VS Code, сетевых дисков.

**Пользователи сервера:** `claude` — Claude Code, tmux, VNC, файлы, без беспарольного sudo; `ccbot` — бот, держит токен, действует от имени `claude` через `sudo -u claude` одним скриптом-помощником. Так обманутый Claude или вредный пакет не может украсть токен, управлять ботом или добавить SSH-ключ.

| На сервере | На ПК (Mutagen, в обе стороны) | Что там |
|---|---|---|
| `~/inbox/` | `C:\Claude\inbox` | всё, что я отдал Claude (Telegram, скриншоты, «Отправить», загрузки Chromium) |
| `~/outbox/` | `C:\Claude\outbox` | готовые файлы для меня; каждый новый дублируется в Telegram |
| `~/chat/` | `C:\Claude\chat` | папка разговоров из бота |
| `~/projects/` | — (только через VS Code) | проекты (git), у каждого может быть свой `CLAUDE.md`; создаются на ПК, в боте только выбираются |

Путь `C:\Claude` одинаковый на всех ПК. Синхронизация — режим без потери данных при конфликте (`two-way-safe`); игнорируются временные файлы Office (`~$*`) и `desktop.ini`.

`~/.claude/CLAUDE.md` = системная часть (пишет установщик) + «Мои инструкции» (из бота). Системная часть: `C:\Claude\…` = `/home/claude/…` (inbox, outbox, chat); готовые файлы — в `~/outbox/`, в ответе путь `C:\Claude\outbox\…`; в терминале VS Code созданный HTML/MD/картинку/PDF открыть командой `code <файл>`.

## 4. Установка и устройства
```
curl -fsSL https://raw.githubusercontent.com/ineuyebok-art/claude-vps/main/install.sh | sudo bash
```
- Один вопрос — токен бота от @BotFather. В конце: IP и страна сервера, код привязки бота, пароль sudo. Меню бота настраивается само.
- Проверяет Ubuntu 24.04; при ошибке — понятная причина. Повторный запуск = обновление, данные и вход в Claude не трогаются.
- **`/devices`** в боте: «Добавить ПК», «Добавить Telegram» (одноразовый код, 15 мин), «Телефон для VNC» (инструкция bVNC), список устройств с кнопкой «Удалить».

## 5. ПК / ноутбук (Windows)
**Строка «Добавить ПК»** (PowerShell, повторный запуск безопасен): ставит недостающее → создаёт SSH-ключ и хост `claude-vps` → ключ в буфер, ждёт → вставляю ключ боту, «Подтвердить» → создаёт `C:\Claude` и синхронизацию (автозапуск Mutagen при входе в Windows), сохраняет пароль VNC (только для моего пользователя Windows), создаёт ярлыки, «Отправить → Claude» и Ctrl+Alt+V. Скрипты берутся из репозитория по фиксированному коммиту.

| Ярлык | Что делает |
|---|---|
| Claude — терминал | Windows Terminal → Claude в tmux-сессии `main`; закрыл окно — работает дальше, открыл — то же место |
| Claude — VS Code | VS Code, подключённый к серверу, папка `~/projects` |
| Claude — рабочий стол | туннель + TigerVNC с сохранённым паролем; закрыл окно — туннель закрылся |
| Claude — файлы | проводник на `C:\Claude` (также закреплена в «Быстром доступе») |

Что где: разговоры и фото — Telegram Desktop; быстро спросить — терминал; код, документы, просмотр — VS Code; вход, оплата, claude.ai — рабочий стол.

## 6. Файлы и предпросмотр
**Отдать файл Claude**
- Telegram: фото, файл, скриншот (Ctrl+V в Telegram Desktop), ссылка на диск. До 20 МБ напрямую, больше — ссылкой (до 2 ГБ).
- Терминал / VS Code:
  - кинуть файл в `C:\Claude\inbox` или перетащить оттуда в окно Claude (путь `C:\Claude\…` Claude понимает);
  - файл из любого места — ПКМ → «Отправить → Claude»: копия в `C:\Claude\inbox`, скрипт ждёт окончания синхронизации и кладёт в буфер `@~/inbox/имя` → Ctrl+V;
  - скриншот — Win+Shift+S → Ctrl+Alt+V: картинка в `C:\Claude\inbox`, после синхронизации в окно вписывается `@~/inbox/screen-<время>.png`;
  - в VS Code — перетащить в его проводник.
- claude.ai на рабочем столе: файл в `C:\Claude\inbox` → «Прикрепить» → папка `inbox`.

**Получить файл**
- Telegram: созданные файлы сразу приходят в чат (отправка до 50 МБ, больше — путь).
- Терминал / VS Code: файл в `~/outbox/` → через секунды в `C:\Claude\outbox`; Claude пишет путь `C:\Claude\outbox\…`, Ctrl+клик — Word/браузер на ПК; копия в Telegram. Файл лежит на ПК — открывается мгновенно и доступен без интернета.

**Предпросмотр (артефактов как на claude.ai в Claude Code нет — результат это файлы)** — в VS Code рядом с Claude, Claude открывает сам:
- Markdown, картинки — встроенный просмотр; HTML — Live Preview (Microsoft), обновляется вживую; PDF — vscode-pdf;
- сайт на `localhost` — VS Code сам пробрасывает порт в браузер ПК;
- docx/xlsx/pptx — Ctrl+клик по `C:\Claude\outbox\…`;
- в Telegram — кнопка «Красиво»; claude.ai с артефактами — на рабочем столе (медленнее).

**Шпаргалка Claude Code** — `C:\Claude\Шпаргалка.html` и `/help` в боте: `@файл`, Ctrl+Alt+V, Esc — стоп, Esc Esc — назад, Shift+Tab — режимы (в т.ч. «сначала план»), `/resume`, `/clear`, `/model`, `!команда`, `cc [имя]`, ответы на разрешения 1/2/3.

## 7. Telegram-бот
**Разговор**
- Любое сообщение (текст, фото, файл, ссылка, пересланный пост) = вопрос; каждое — отдельный вопрос, альбом — один.
- Ответ печатается по ходу в одном сообщении; Markdown → форматирование Telegram, таблицы — моноширинно.
- Пока Claude отвечает, новое сообщение идёт параллельно веткой текущего разговора (`--resume <id> --fork-session`).
- Reply на сообщение бота — в тот разговор; обычное сообщение — в разговор последнего ответа; новый — только `/new`.
- Бот запускает Claude сразу; задачи tmux — с `nice 10`, бот всегда отвечает первым.
- Кнопки под каждым ответом: «Короче», «Подробнее», «Файлом» (`.md`), «Красиво» (`.html` с таблицами и формулами, KaTeX встроен, открывается офлайн).

**Команды**
| Команда | Что делает |
|---|---|
| `/new` | новый разговор |
| `/project` | выбрать проект кнопками; по умолчанию `~/chat` |
| `/sessions` | последние разговоры (терминал, VS Code, оба Telegram) — «Продолжить» |
| `/run <задача>` | долгая задача в tmux в текущем проекте; предупреждает, если там уже идёт задача |
| `/tasks` | работает / ждёт тебя / готово / прервана; «Смотреть», «Стоп» |
| `/devices` | устройства (раздел 4) |
| `/status` | IP и страна сервера, вошёл ли Claude, Organization ID, диск, загрузка; «Быстро / Умно», «Мои инструкции» |
| `/help` | шпаргалка и правила безопасности |

- «Смотреть» — экран задачи в одном обновляемом сообщении, кнопки 1/2/3/Enter/Esc; reply текстом — в задачу. «Стоп» — задача со всеми дочерними процессами.
- Уведомления (хуки Stop, Notification во всех tmux-сессиях): «готово» / «ждёт тебя» + начало ответа + «Смотреть»; на оба аккаунта.
- «Быстро / Умно» — `--model sonnet` / `opus`, по умолчанию «Умно», для каждого аккаунта.
- Разрешения: без вопросов — чтение, поиск в интернете, правка файлов в текущем проекте, `~/inbox`, `~/outbox`; остальное — «Разрешить» / «Разрешать всегда» / «Нет».

## 8. Рабочий стол сервера и вход в Claude
- ПК — ярлык; Android — bVNC со встроенным SSH-туннелем (инструкция в `/devices`).
- Сразу открыты Chromium и терминал; размер под окно; общий буфер обмена; раскладки EN/RU (Alt+Shift); загрузки — `~/inbox` (→ `C:\Claude\inbox`).
- Вход и оплата: Chromium → claude.ai → вход, Organization ID в Settings → Account, оплата своим способом; терминал → `claude` → вход откроется в том же Chromium, без копирования кодов.
- Бот во входе не участвует, `/status` показывает только результат.

## 9. Безопасность и надёжность
- SSH: только ключи; root и пароли выключены; `AllowUsers claude`; без agent forwarding. Ключи — `/etc/ssh/authorized_keys/claude`, владелец root; добавляет только бот после «Подтвердить».
- Firewall (ufw): открыт только 22; VNC — localhost + пароль; Mutagen — по тому же SSH-ключу.
- Сторож раз в минуту, тревога в бот: изменились SSH-ключи; новые cron/systemd-юниты пользователя `claude`; исходящий SSH-туннель (`ssh -R`, `autossh`) — следы бэкдора из поддельного расширения Claude Code (октябрь 2026). Агент Mutagen — не тревога.
- Бот отвечает только привязанным аккаунтам; коды одноразовые; повтор update не перезапускает Claude; ссылки только с доменов Google, Яндекс Диска, Dropbox; имена файлов очищаются; входящие файлы не исполняются.
- Токен бота — только у `ccbot` (0600); пароли VNC и sudo — 0600; секреты не в git, логах и сообщениях.
- Бот, задачи tmux, VNC — systemd с автоперезапуском. После перезагрузки задачи помечаются «прервана», сами не перезапускаются, продолжаются кнопкой. Синхронизация `C:\Claude` догоняет сама после сна и без интернета. Код — в GitHub; бэкапов нет (файлы `inbox`/`outbox` есть и на ПК, и на сервере). Автообновления безопасности Ubuntu.
- Памятка (в `/help`): VS Code и расширения — только Microsoft Marketplace (не Cursor/VSCodium/Windsurf); облачный пароль в Telegram; за границей — местная SIM/eSIM или Wi-Fi, не роуминг; удалённый в `C:\Claude` файл удаляется и на сервере; при тревоге — удалить устройство в `/devices`, выйти из claude.ai во всех сеансах, `sudo claude-vps token`.
- **Нельзя:** пользоваться Claude вне стран, где он доступен; прокси учётных данных (CLIProxyAPI и т.п.), модифицированный Claude Code, чужие/общие аккаунты; `--dangerously-skip-permissions`; VNC наружу; рабочий код и секреты работодателя на сервере.

**Аудит 05.11.2026** (настоящий `claude` 2.1.318 по настоящему SSH, запись всех запросов к API)
- В запросах к API адреса ПК нет: ни при обычной работе, ни после `env`, `who`, `last`. Проверено на поддельном API; IP, который видит Anthropic, — это адрес сервера, потому что соединение открывает сервер.
- Исправлено: вход из терминала VS Code открылся бы на ПК (теперь любая ссылка открывается в Chromium сервера); адрес ПК лежал в `SSH_CONNECTION`, в том числе в tmux, и в `who`/`last`; чтение без вопросов открывало учётные данные Claude; Claude поставил бы расширение в VS Code; первая задача `/run` застревала на диалоге доверия; токен попадал в аргументы `curl`.
- Остаётся: `ss -tn` на сервере показывает адрес подключённого ПК, без отдельной сети для Claude это не закрыть. Сервер не прикрывает заход на claude.ai, приложение Claude и клики по таким ссылкам с самого устройства. На ПК по решению владельца только предупреждение, без блокировки в `hosts`.

**Отступления от ТЗ**
- Ctrl+клик: Windows Terminal не открывает путь `C:\…`, поэтому Claude пишет две строки — `file:///C:/Claude/outbox/…` и обычный путь. В tmux выключена мышь, иначе она перехватит клик; прокрутка остаётся за окном терминала.
- Пароль VNC бот не присылает: для bVNC он берётся на ПК командой `claude-vps info`.
- Добавлен второй узкий помощник `keys` от root: файл ключей принадлежит root, `sudo -u claude` его не изменит.
- Добавлена команда `code` на сервере: иначе из tmux файл не открылся бы в VS Code.
- В `sudo` выключен кэш пароля. Защита раздела 3 не абсолютна: пароль, введённый в терминале обманутого Claude, можно перехватить, поэтому при тревоге токен меняется из консоли хостера.
